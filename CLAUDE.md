# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

This repo holds two parallel multilingual deliverables for Haroune Mohammedi's personal resume:

1. **Static site** served at `haroune.me`. Locale data lives in `locales/{en,fr}.mjs`; one shared template in `site/template.mjs` renders both pages. `build.js` (zero-dep Node) emits `dist/index.html` (English) and `dist/<lang>/index.html` (e.g. `dist/fr/index.html`).
2. **Printable PDF CV** built with XeLaTeX. Layout and typography in `PlushCV.cls` at the repo root (shared); per-locale content in `cv/en/resume.tex` and `cv/fr/resume.tex`.

The two deliverables intentionally have **separate sources** (the website covers more material than the one-page PDF), but they share content conventions and must stay in sync on the load-bearing facts (roles, dates, headline metrics, stack).

## Languages

- `en` — English (default; served at `/`)
- `fr` — French (served at `/fr/`)
- `ar` — Arabic (scaffolded only — see "Adding Arabic" below)

Adding a new locale to the site is a single step: drop `locales/<lang>.mjs` and rerun `make site`. `build.js` discovers locales, generates per-locale HTML, and wires hreflang + sitemap alternates automatically.

## Build & preview commands

```sh
make site         # build the static site into dist/
make pdf-en       # compile dist English PDF → haroune_mohammedi_resume.pdf
make pdf-fr       # compile dist French PDF  → haroune_mohammedi_cv_fr.pdf
make pdf          # both PDFs
make all          # pdfs + site (full reproducible build)
make serve        # build, then serve dist/ on http://localhost:8000
make clean        # remove dist/ and LaTeX intermediates
```

Preview the site locally with `make serve` (the site uses relative asset paths, so any static server rooted at `dist/` works — `python3 -m http.server 8000 --directory dist` is equivalent).

PDFs are built locally and **committed to the repo root** (`haroune_mohammedi_resume.pdf`, `haroune_mohammedi_cv_fr.pdf`). `build.js` picks them up from there and stages them into `dist/`. Rebuild before pushing if the `.tex` sources changed: `make pdf`.

## Deployment

GitHub Pages, driven by `.github/workflows/pages.yml`. On every push to `master` the workflow:
1. checks out the repo,
2. sets up Node 20,
3. runs `node build.js`,
4. uploads `dist/` as the Pages artifact.

The repo's Pages source is set to "GitHub Actions" (not "Deploy from a branch"). The workflow does **not** rebuild PDFs in CI — they're built locally and committed.

## Site architecture

### Source layout

```
locales/
├── en.mjs                # English strings (default + reference)
└── fr.mjs                # French strings (translation conventions in header)
site/
├── template.mjs          # render(locale, alternates) → HTML string
├── css/styles.css        # design system, RTL-ready via CSS logical properties
├── js/main.js            # canvas animation, scroll-spy, hamburger (locale-agnostic)
└── public/               # static files copied verbatim into dist/ root
    └── CNAME
build.js                  # build orchestrator (Node, zero deps)
dist/                     # output — gitignored, regenerated by CI
```

### Locale data

Locale files are ES modules exporting a single object. Each contains `htmlLang`, `dir`, `ogLocale`, `cvFile`, plus the page strings keyed by section (`meta`, `nav`, `hero`, `about`, `experience`, `skills`, `projects`, `education`, `contact`, `footer`, `langSwitcher`). String values may contain limited inline HTML (`<strong>`, `<span class="hl">`, etc.) — interpolations are author-controlled at build time, so the template does not HTML-escape.

When editing copy, edit the locale file — **not** the rendered HTML in `dist/`.

### Template

`site/template.mjs` exports `render(t, alternates)` which returns the full HTML string for one locale. It also exports `localePath(htmlLang)`. The template emits:
- `<html lang dir>` matching the locale
- localized `<title>`, `<meta description>`, Open Graph + Twitter tags
- `<link rel="canonical">` + `<link rel="alternate" hreflang>` for every locale + `x-default`
- JSON-LD `Person` schema
- A `.nav-lang` language switcher in the nav (and slide-out mobile menu)

All in-page asset and PDF URLs are **relative** (e.g., `css/styles.css`, `../haroune_mohammedi_cv_fr.pdf`) so file-system previews work and the same template serves correctly from any subdirectory depth.

### CSS

Design tokens on `:root` in `site/css/styles.css`: colors (`--bg`, `--surface`, `--orange` #f97316, `--cyan` #22d3ee) and font stacks (`--font-display`, `--font-body`, `--font-mono`). Use the tokens — never hard-code hex or font-family.

The stylesheet is direction-aware: every horizontal property uses CSS logical equivalents (`margin-inline-end`, `inset-inline-start`, `padding-inline-start`, `border-inline-start`). A small number of `[dir="rtl"]` overrides handle cases logical properties can't express — the `→` bullet glyph (flipped to `←`), the mobile menu slide-in transform, and `.project-card::before`'s `transform-origin`. Direction-neutral block-axis properties (`top`, `bottom`) are kept as-is.

Font swaps for Arabic are scaffolded via `[lang="ar"]` overrides on the font tokens — Cairo + IBM Plex Sans Arabic. Loading those families is gated on shipping `ar.mjs`.

### JS

`site/js/main.js` is locale-agnostic — no user-facing strings, only DOM hooks. Four IIFEs: canvas pipeline animation (honors `prefers-reduced-motion`), nav scroll-spy, hamburger toggle, fade-in IntersectionObserver. Section IDs (`hero`, `about`, `experience`, `skills`, `projects`, `education`, `contact`) are the contract — the scroll-spy depends on them and they must not change.

## PDF (LaTeX) architecture

```
PlushCV.cls               # shared class — typography, layout, macros (no strings)
cv/
├── en/resume.tex         # English content
└── fr/resume.tex         # French content
```

The class file lives at the repo root (not `cv/`) so XeLaTeX finds it via the default class-search path when compiling from the repo root.

Engine: **XeLaTeX** (required for `fontspec` + `polyglossia`).

Language is selected via the class option: `\documentclass[english]{plushcv}`, `\documentclass[french]{plushcv}`, `\documentclass[arabic]{plushcv}`. polyglossia handles month names, quotation marks, and uppercase casing of accented letters (`\MakeUppercase` correctly handles É, È, etc.). `\today` follows the document language.

Each compile must run **from the repo root** so the class file, `fonts/`, and `icons/` resolve correctly — the Makefile targets do this. Per-locale output goes to `cv/<lang>/resume.pdf`, then is copied to the canonical `haroune_mohammedi_resume.pdf` (en) or `haroune_mohammedi_cv_fr.pdf` (fr) at the repo root.

**One-page constraint:** the PDF must fit on one page. French is typographically ~15–20% denser than English, so the French source uses tighter phrasing and fewer bullets per role. When adding content, trim elsewhere. Overflow silently spills onto page 2 with broken alignment.

## Content positioning (important)

The resume leads with **Senior Data Engineer** positioning. MLOps experience is intentionally kept only in the About section and the BigMama experience entry — it is **not** surfaced in the hero, tagline, skills pills, or section titles. Preserve this when editing both locales. The goal: lead with the positioning most relevant to the target audience (data engineering roles) while still including MLOps in a way that doesn't dilute the core narrative — maximizing chances of Senior / Architect Data Engineering interviews.

### Translation conventions (FR)

- Job titles like "Senior Data Engineer", "Data Architect" **stay in English** — these are the actual search terms recruiters use in the French tech market.
- Tech vocabulary (pipeline, stack, monitoring, scalable, dataset, …) stays untranslated where it's the natural word in French tech writing.
- Section labels follow French CV norms (`Expérience`, `Formation`, `Compétences`) rather than literal translations.
- Month abbreviations: `Janv., Févr., Mars, Avr., Mai, Juin, Juil., Août, Sept., Oct., Nov., Déc.`
